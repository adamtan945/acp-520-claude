Rovo 的管理與治理

Rovo 是 2026 年新版考試新增的主題，舊版考綱沒有。這一節考你 Rovo 預設開在哪裡、怎麼封鎖 app、Enterprise 的 allowlist 與 blocklist，以及 Rovo settings、agents、Studio、用量分析等治理控制。

3 分鐘速覽

Rovo：預設開啟，org admin 決定哪裡關、誰能用

  1. Rovo 預設開啟Standard、Premium、Enterprise 方案的 app 都自動啟用 Rovo，organization 裡每個人都能用。Atlassian Government Cloud 沒有 Rovo。Sandbox 的說法有兩種：About AI 頁寫要手動啟用，Test drive 頁寫 2025 年 4 月 14 日之後建立的 sandbox site 會自動啟用。
  2. Rovo accessOrg admin 在 Rovo → Rovo access 封鎖（block）某個 app。被封鎖的 app，現在與之後的 AI 功能都關閉，包含 Agents 與 Chat；之前產生的內容保留。
  3. Jira 家族要全部封鎖同一個 site 上封鎖一個 Jira 家族 app，只關那個 app。Rovo Search、Chat、Create with Rovo 要等該 site 所有 Jira app 都封鎖才會關。
  4. Enterprise 的 allowlist新介面可以用 app 與 group 一起控制。Default access 關閉時，app 與 group 都要加進 allowlist；開啟時，app 或 group 任一個被 block 就不能用。
  5. Rovo settings 與 agentsWeb search、Beta features、Search bookmarks 是 organization 層級設定；Rovo → Agents 的 Default access 決定之後新建的 agent 能碰哪些 app 與 group。
  6. 看用量Rovo → Rovo trends 看 adoption 與 agents 的趨勢，每 48 到 72 小時更新，可匯出 CSV；Rovo credit 的實際用量要看 Insights → Platform usage。

  • Manage Rovo accessCertain AI features common across Jira family apps, such as Rovo AI-powered Search, Chat, and Create with Rovo, remain available as long as any Jira app on that site still has Rovo enabled.

Rovo 是什麼

誰有 Rovo、資料與權限

項目官方說法

Rovo Standard（beta）：讓沒有 Jira、Confluence 等付費訂閱的人也能用 Rovo，等於把 Rovo 當成一個獨立的 app。Organization 升級到 Rovo Standard 後，才能指派 Rovo Standard user 角色，而且要在每個需要的 site 上指派（直接給、透過 group、邀請時給都可以）。已經從其他付費訂閱取得 Rovo 的人，被指派這個角色也不會變成 Rovo Standard 的計費使用者。除了 org admin，Rovo Standard user access admin 也能指派這個角色，但只能管 Rovo Standard 的存取。

上線前先找隱私與資安團隊

官方建議啟用 AI 或 Rovo 之前，先和隱私與資安團隊確認符合組織需求。Rovo 處理的資料用 SSL 加密傳輸，但部分 AI 供應商可能在歐盟以外的地區處理資料。

Rovo access

封鎖 app（Standard、Premium）

  1. 位置Atlassian Administration›Rovo›Rovo access。
  2. 選 app按 Add app，清單會列出有 Rovo 功能的 app，勾選要關閉 Rovo 的 app。
  3. 確認檢查選擇後按 Block access。表格會列出沒有啟用 Rovo 功能的 app。
封鎖之後結果
該 app 的 AI 功能現在與之後的 AI 功能都關閉，Agents 與 Chat 也一起關閉
之前用 Rovo 產生的內容保留，不會被刪除
同一個 site 的其他 Jira 家族 app不受影響；只關掉被封鎖的那個 app
Jira 家族共用的 Search、Chat、Create with Rovo只要該 site 還有一個 Jira app 啟用 Rovo 就還在；要全關，就把該 site 所有 Jira app 都封鎖

Bitbucket Cloud 不在 Rovo access 頁管理：要在 workspace 的 Workspace settings → AI 同意 AI 條款，再按 Activate 或 Deactivate，影響整個 workspace 的 pull request。Jira Service Management 也可能要在自己的 admin 設定再調整 Rovo 功能。

本段必考
  • Rovo → Rovo access → Add app → Block access。
  • 封鎖不會刪除已產生的內容；Jira 家族要全部封鎖，共用功能才會關。

Enterprise

Allowlist、blocklist 與 Atlassian-hosted LLMs

Default access 開啟

沒被 block 的都能用
  • App 或 group 任一個被 block 就不能用
  • 例如使用者在允許的 group，但在被 block 的 app 裡仍不能用
  • 用 Add app 或 Add group，再按 Block access

Default access 關閉

只開放給 allowlist
  • App 與使用者的 group 都要加進 allowlist
  • 只加 app、沒加 group 時，使用者還是不能用
  • 用 Add 選 app 或 group，再按 Allow access

Enterprise 的 Rovo 存取控制正在更新。如果你只看到 blocklist 的選項，就是原始介面，操作和 Standard、Premium 一樣只能封鎖 app。

Atlassian-hosted LLMs：Enterprise 專用，套用在整個 organization，而不是個別 site。開啟後，Rovo 只用 Atlassian Cloud 邊界內的 LLM，客戶資料不會離開這個邊界；代價是 Rovo credit 費率較高，部分功能（例如語音）可能不能用。目前沒有自助開關，要找 Atlassian account team 或 support 申請。

本段必考
  • Default access 關閉：app 與 group 都要 allow。
  • Default access 開啟：app 或 group 任一個被 block 就不能用。
  • Atlassian-hosted LLMs：Enterprise、org 層級、要申請。
資料來源（6）有疑慮時點開看官方原文

  • Manage Rovo access for EnterpriseIf default access is enabled, access is restricted if either the app or the user group is blocked.

治理控制

Rovo settings、agents、Studio 與 connectors

設定位置重點
Web searchRovo → Rovo settings → Web search開啟後，使用者可以把 Rovo 的來源切換或擴大到公開網站；Rovo Chat 與 Studio 的 agent 設定會出現開關
Beta featuresRovo → Rovo settings → Beta features預設使用者能先用 beta 的 Rovo 功能；關閉後要等正式推出才拿到，但不是所有功能都受這個設定控制
Search bookmarksRovo → Rovo settings → Search bookmarks讓特定搜尋字詞顯示指定網址；Rovo 不檢查目的連結的權限，所以所有人都看得到
未來 agent 的 default accessRovo → Agents → Default access設定之後新建的 agent 預設能存取哪些 app 與 group；既有的 agent 要到各自的 profile 改
Studio 的建立權限Studio → Studio settingsStudio 是獨立 app；有 Studio 存取的人預設都能建 automation 與 app，要限制給特定 group 就在這裡改
Teamwork Graph connectors需要 admin 設定的 connector 由 org admin 設定；Smart Link connector 不需要 admin 設定把第三方 app 接給 Rovo 的 Search、Chat、Agents；遵守第三方 app 的權限；org admin 中斷連線後 30 天內刪除已索引的內容（GitHub 另有規則）
Studio app admin 可以繞過 agent 的建立限制

Studio 變成獨立 app 時，原本有 Jira、Confluence、JSM User 角色的人會自動拿到 Studio 的 user 角色；這些 app 的 app admin 也會成為 Studio 的 app admin（只限原本就有舊版 Studio 的 organization）。Studio app admin 有完整的建立權限，即使 org admin 之前限制他在其他 app 建 agent，他在 Studio 仍能建。所以要到 Atlassian Administration 檢查 Studio 的角色，並在 Studio settings 限制建立權限。

管理單一 agent（Rovo → Agents → 選 agent，Grant access 給 app 或 Add to group）的官方頁，列出的方案是 Atlassian Guard Premium；設定未來 agent 的 default access 則是 Standard、Premium、Enterprise 都可以。

本段必考
  • Web search、Beta features、Search bookmarks 都在 Rovo settings。
  • Bookmark 不檢查權限；Studio app admin 可以繞過 agent 建立限制。

用量與測試

Rovo trends、在 sandbox 試用、轉移前的處理

Rovo trends 分頁指標
AdoptionUsers with AI enabled（啟用 Rovo 的 app 中的不重複使用者）、Active users（實際用過 Rovo 的人）、Rovo interactions（LLM 被要求產生內容的次數）
AgentsActive agents（至少被用過一次的 agent）、Agent runs（被使用者或 automation 觸發的次數）、Agents created（新建的自訂 agent）
  • 位置是 Rovo → Rovo trends；Standard、Premium、Enterprise 的 org admin 可以看。
  • 數據每 48 到 72 小時更新；預設期間是 Last 4 weeks，百分比是和前一期比較。
  • 按右上角的下載圖示選 Export 匯出 CSV，檔案準備好會寄 email 通知。
  • Rovo trends 可能包含不算 Rovo credit 的 AI 功能；要看 credit 的實際用量，去 Insights → Platform usage。
  1. 試用條件在 sandbox 試 Rovo 要是 org admin、已啟用 Rovo、Premium 或 Enterprise 方案、不在 Government Cloud，而且是新的 billing 體驗。
  2. 建 sandboxApps → Sandboxes 建一個 Confluence、Jira 或 JSM 的 sandbox。
  3. 啟用 Rovo2025 年 4 月 14 日之後建立的 sandbox site，會在 15 分鐘內自動啟用 Rovo；較早的，在 sandbox site 那一列（不是 app 那一列）的 More actions 選 Activate Rovo。
  4. 停用同一個位置選 Deactivate Rovo，sandbox 可以繼續用。

轉移與特殊環境：把 app 轉移到別的 organization 前，Rovo 訂閱要請 billing support 停用，每個 app 的 AI 也要先關掉，轉移後再在新 organization 啟用。HIPAA 環境要用 Rovo，需要聯絡 Atlassian Support 開通。

本段必考
  • Rovo trends：48 到 72 小時更新、可匯出 CSV；credit 看 Platform usage。
  • Sandbox 的 Rovo 在 site 那一列啟用，不是 app 那一列。

實作 Lab：封鎖 Jira 的 Rovo，再巡一遍 Rovo 設定

約 20 分鐘Org admin；Jira 為 Standard 以上（Rovo 適用 Standard、Premium、Enterprise 的 app；可沿用 520.2.2 的 Premium 試用）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：用 Rovo access 封鎖一個 app、用 Leo 看差異，再巡一遍 Rovo settings、Agents 的 Default access 與 Rovo trends。

這個 Lab 對應的考點

Standard 以上的 app 預設自動啟用 Rovo；在 Rovo → Rovo access 用 Add app → Block access 封鎖；封鎖會關掉該 app 現在與之後的 AI 功能（含 Agents、Chat），但保留已產生的內容。

準備

  • labjira 的 Jira 是 Standard 以上的方案（含試用）。
  • Leo 能登入 labjira 的 Jira。

步驟

  1. 你應該看到：Standard 與 Premium 的畫面是一張封鎖清單；還沒封鎖任何 app 時，表格通常是空的，因為 Rovo 預設已經啟用。
  2. 你應該看到：通常看得到 Rovo 的入口（例如 Chat 或 AI 按鈕）；確切位置依介面版本不同。
  3. 你應該看到：表格出現 labjira 的 Jira，代表這個 app 沒有 Rovo 功能了。
  4. 你應該看到：Jira 裡的 AI 功能與 Agents、Chat 消失。labjira 上沒有其他啟用 Rovo 的 Jira 家族 app，所以 Jira 家族共用的 Search、Chat 通常也一起關掉。
  5. 你應該看到：Web search 是一個開關；Beta features 的 Enable beta features 預設開啟；Search bookmarks 列出已建立的 bookmark。
  6. 你應該看到：可以用 Add 選 Apps 或 Groups，設定之後新建的 agent 預設能存取哪些 app 與 group；既有 agent 不受影響。
  7. 你應該看到：預設期間是 Last 4 weeks；Lab Org 幾乎沒有用量，所以數字很少或是空的，資料每 48 到 72 小時才更新。

讀完了？用這張收攏整節

預設開、要關用 blockStandard 以上自動有 Rovo；在 Rovo access 封鎖不要的 app。
Jira 家族全關才算關共用的 Search、Chat、Create with Rovo，要該 site 所有 Jira app 都封鎖才會關。
Enterprise 關預設：app、group 都要 allowDefault access 開啟時則是任一個被 block 就不能用。
誰有 Rovo、資料與權限
  • Standard 以上自動有 Rovo，每個人都能用；Government Cloud 沒有。
  • Rovo 遵守 app 權限；site 上任一 app 開 AI，Rovo 就能用同 site 所有 app 的資料。
封鎖 app（Standard、Premium）
  • Rovo → Rovo access → Add app → Block access。
  • 封鎖不會刪除已產生的內容；Jira 家族要全部封鎖，共用功能才會關。
Allowlist、blocklist 與 Atlassian-hosted LLMs
  • Default access 關閉：app 與 group 都要 allow。
  • Default access 開啟：app 或 group 任一個被 block 就不能用。
  • Atlassian-hosted LLMs：Enterprise、org 層級、要申請。
Rovo settings、agents、Studio 與 connectors
  • Web search、Beta features、Search bookmarks 都在 Rovo settings。
  • Bookmark 不檢查權限；Studio app admin 可以繞過 agent 建立限制。
Rovo trends、在 sandbox 試用、轉移前的處理
  • Rovo trends：48 到 72 小時更新、可匯出 CSV；credit 看 Platform usage。
  • Sandbox 的 Rovo 在 site 那一列啟用，不是 app 那一列。
