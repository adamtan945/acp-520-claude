Release tracks 與 sandboxes

Atlassian 持續推出變更。這一節考你怎麼用 release tracks、defer 與 freeze window 控制變更何時到達，以及怎麼用 sandbox 先測試、複製資料與部署設定。

3 分鐘速覽

Release tracks 控制變更何時到；sandbox 讓你先測

  1. 三種 release trackContinuous 是預設，變更一推出就收到；Bundled 把大部分變更集中在每月第二個週二推出；Preview 只給 sandbox，比 production 早一個月收到同一包。
  2. 方案與位置Release tracks 要 Jira、Jira Service Management、Jira Product Discovery 或 Confluence 的 Premium 或 Enterprise 方案；由 org admin 在 Apps → Release management → Release tracks 切換。
  3. Bundled 也擋不住的變更Bug fix、安全與效能更新、Opsgenie 支援的 JSM 功能，以及長期逐步推出的大型變更，即使在 bundled track 也會立即推出。
  4. Defer 與 freeze window兩者都要 Enterprise。Defer 讓單一變更延後至少 30 天；freeze window 最多 60 天前排定，在期間擋住可見變更，但 sandbox 不能放進去。
  5. Sandbox 數量與存取Premium 每個 app 有一個免費 sandbox，Enterprise 每個 app 最多五個。剛建好時只有 org admin 能進；sandbox 不在 SLA 範圍內。
  6. Sandbox 生命週期Online 的 sandbox 停用或 28 天沒用會變 Offline；Offline 30 天內可以還原，之後永久刪除。Production 不再是 Premium 或 Enterprise 時，sandbox 會被銷毀。

Release tracks

三種 release track 各收到哪些變更

Track誰能用什麼時候收到包含哪些變更
Continuous（預設）App 與 sandbox變更一推出就收到所有變更：新功能、改進、bug fix、安全與效能更新、移除 app 或功能
BundledApp（官方只描述 app 使用）每月第二個週二 22:00 UTC 起一起推出；時間不能自訂需要使用者調整工作方式、但對組織影響不大的可見變更，例如移動按鈕、新設定、Jira workflow 多一個步驟
Preview只有 sandbox比 production 早一個月收到和 bundled track 相同的那一包變更

Bundled track 也不會延後的變更：bug fix 與安全、效能更新；Opsgenie 支援的 Jira Service Management 功能；長時間逐步推出的可見變更，例如移除某個 app 或功能，或像 Jira 新 issue 介面、Confluence fabric editor 這種大型變更。這些變更不管你選哪個 track 都會立即推出。

Jira 的變更現在依季節週期（seasonal release cycles）推出。Jira 在 bundled track 上時，不在季節週期內的月份，那一包可能沒有什麼變更。

本段必考
  • Preview 只給 sandbox；production 只能選 Continuous 或 Bundled。
  • Bundled 擋不住 bug fix 與安全、效能更新。

切換

切換 track 與建議的組合

  1. 位置Atlassian Administration›Apps›Release management›Release tracks。
  2. 選對象在表格找到要改的 app 或 sandbox，按 Change track。
  3. 選 trackApp 選 Bundled（或改回 Continuous）；sandbox 選 Preview。
  4. 確認按 Next，再按 Confirm。
  • App 剛切到 bundled track 時，第一包可能是零個或很少變更，因為大部分變更在 continuous track 時已經推出了。
  • 切回 continuous track 後，app 幾分鐘內就會開始收到變更。
你想要ProductionSandbox說明

控制上線

Defer、freeze window 與四種選項

選項怎麼設定方案
所有變更立即收到App 與 sandbox 都留在 Continuous（這是預設）—
大部分立即收到，延後某些App 留在 Continuous、sandbox 改 Preview，並允許 org admin deferDefer 要 Enterprise
每月一包App 改 Bundled、sandbox 改 PreviewPremium 或 Enterprise
關鍵期間擋住變更排一個 freeze window，把要保護的 app 放進去Enterprise

Defer a change

延後單一變更
  • 只適用 continuous track 上的 app
  • 先在 Apps → Release management → App updates 按 Allow admins to defer changes；允許之後，Atlassian 的 experiments 不再推給你們
  • 變更在 App updates 公告後，有 10 天可以 defer
  • Defer 之後至少 30 天不會推到 Enterprise 方案的 app，包含 continuous track 上的 sandbox

Freeze window

一段時間擋住可見變更
  • 位置：Apps → Release management → Freeze windows
  • 最多 60 天前排定，不能在開始前 48 小時內建立
  • 擋住可見變更、已 defer 的變更與 bundled 那一包
  • Bug fix、安全與效能更新、長期大型變更照常推出
  • Sandbox 不能放進 freeze window

預設情況下，org admin 不能延後任何變更，需要停機的變更會在預設的 maintenance window 推出。不同 app 可以選不同的選項，例如 Jira 用 Bundled、Confluence 留在 Continuous。

本段必考
  • Defer 與 freeze window 都要 Enterprise。
  • Defer：公告後 10 天內、延後至少 30 天；freeze：最多 60 天前排、不含 sandbox。

Sandbox

Sandbox 是什麼、有幾個、誰能進

項目重點
是什麼與 production 隔離的測試環境；網址和 production 相似，subdomain 可以自己取（例如 dev、test、uat）
哪些 app 可以有Premium 或 Enterprise 方案的 Jira、Jira Service Management、Jira Product Discovery、Confluence
免費幾個Premium：每個 app 一個；Enterprise：每個 app 最多五個，可以分配給不同的 production site
Free 與 Standard不能建 sandbox；Standard 可以用 30 天的 Premium 試用暫時體驗
想要更多年約方案的 app 可以加購 sandbox，以 add-on 另外計費
使用者上限和連結的 production 環境一樣
帳單聯絡人建立 sandbox 的人會成為 sandbox 的 billing 與 technical contact
SLASandbox 不是 production，不在 SLA 範圍內，不要把它當成資料的唯一存放處

誰能進 sandbox：剛建好時只有 org admin 能進。要讓其他人測試，到 Apps → Atlassian apps，在該 sandbox 的 More actions 選 Manage users，把人加進 sandbox 專用的 group；group 名稱會像 jira-users-test-sandbox-123。Centralized user management 的使用者與 group 在 organization 層級，不需要複製到 sandbox。

不要把 Atlassian Guard 加到 sandbox

官方不建議在 sandbox 加 Atlassian Guard：刪除含有 Atlassian Guard 的 sandbox，可能讓 production 也無法使用 Guard。

本段必考
  • Premium 一個、Enterprise 最多五個（每個 app）；Free 與 Standard 沒有。
  • 剛建好只有 org admin 能進；其他人要加進 sandbox 的 group。

生命週期

建立、停用、還原、重設

  1. 建立Atlassian Administration›Apps›Sandboxes，按 Create sandbox。
  2. 選來源選 source production site；sandbox 只能建給這個 site 上的 app。
  3. 取名輸入 sandbox site 的名稱，它會變成 sandbox 的網址。
  4. 選 app選要複製的 app，最多 30 分鐘建好，完成會寄 email。之後要在同一個 sandbox site 加其他 app，就在表格那一列按 Add。
動作效果注意
Deactivate sandboxSandbox 變成 Offline，不影響 production30 天內可以連同資料 Restore
Deactivate sandbox URL整個 sandbox site 停用，裡面所有 sandbox 都停用Site 永久刪除 30 天後，才能重用這個網址
Restore把 Offline 的 sandbox 連資料一起還原還原任一個 sandbox 會一起還原 site；還原 site 不會還原所有 sandbox
Reset永久刪除所有資料（含 Marketplace app），保留 sandbox只能對 Online 的 sandbox 做、不能復原；Jira 家族的 sandbox 會一起被重設
Update sandbox URL改 sandbox 的 subdomain同一個 sandbox site 的所有 sandbox 一起改
Sandbox 會被銷毀的情況

Sandbox 連結著 production。Production 的 app 不在了，或 production 的 app 不再是 Premium 或 Enterprise 方案時，sandbox 會被銷毀，資料與設定都不能還原。沒在用的 sandbox 會在變成 Offline 前 7 天寄 email 給所有 org admin。

本段必考
  • 28 天沒用變 Offline；Offline 30 天內可 Restore，之後永久刪除。
  • Reset 只能對 Online 的 sandbox 做，而且不能復原。

資料

把資料複製進來、把設定部署出去

Copy production data

Production → sandbox
  • 位置：Apps → Sandboxes → 該 sandbox 的 More actions → Copy production data
  • 可以選全部 spaces／projects，或指定幾個；可以選要不要附件
  • 每次複製都會覆蓋 sandbox 裡現有的資料
  • Jira 家族選複製全部時，另外兩個已建立的 Jira 家族 sandbox 也會一起被覆蓋
  • Confluence 要同時是 org admin 與 app admin 才能複製

Create deployment

Sandbox → production 或其他 sandbox
  • Beta 功能，要 Premium 或 Enterprise 的 Jira
  • 位置：該 sandbox 的 More actions → Create deployment，再選目的地
  • 只部署 company-managed project 的設定（workflow、scheme、custom field、request type 等）
  • 會自動勾選相依的設定；media（例如 request type 圖示）不會部署
  • 完成後到 View deployment log 下載報告檢查
複製時的處理例子
不會複製Marketplace app 與其資料；access settings（要自己把人加進 group，權限才會生效）；Confluence 的 private spaces
複製但先停用Automation flows 以停用狀態複製，避免在 sandbox 意外執行；JSM 的 portal-only 帳號以 inactive 狀態複製
本段必考
  • Copy 每次都覆蓋 sandbox 的資料；Marketplace app 與 access settings 不會複製。
  • Deploy 只支援 company-managed project 的設定。

動手做

實作 Lab：切 Bundled、建 sandbox、讓 Leo 進去

約 30 分鐘Org admin；Jira 為 Premium（用 Premium 試用；Free 與 Standard 沒有 release tracks 與 sandbox）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：把 Jira 從 continuous 切到 bundled track，建一個 Jira sandbox、複製資料、讓 Leo 進去，最後把 sandbox 設成 Preview track。

這個 Lab 對應的考點

Release tracks 要 Premium 以上；Preview 只給 sandbox；推薦組合是 production Bundled＋sandbox Preview。Sandbox 剛建好只有 org admin 能進；Copy production data 每次都會覆蓋；Offline 30 天內可以 Restore。

準備

  • labjira 的 Jira 已開始 Premium 試用（依 Atlassian Administration 的方案頁操作）。
  • labjira 的 Jira 至少有一個 space 與幾張 work item，可以複製進 sandbox。

步驟

  1. 你應該看到：labjira 的 Jira 是 Continuous，這是預設值。
  2. 你應該看到：Jira 那一列變成 Bundled。官方說切換後的第一包可能是零個或很少變更。
  3. 你應該看到：最多 30 分鐘建好，會收到 email。表格中這個 sandbox 是 Online，Last data copy 顯示 Never copied。
  4. 你應該看到：Leo 進不去：sandbox 剛建好時只有 org admin 能進。
  5. 你應該看到：Leo 能進 sandbox 了，但裡面還沒有 production 的資料。
  6. 你應該看到：完成後 Last data copy 顯示日期，sandbox 裡出現 production 的 space 與 work item；如果 production 有 automation rules，複製過來會是停用狀態。
  7. 你應該看到：Sandbox 變成 Preview。Production 的 Jira 那一列通常不會有 Preview 可以選，因為 Preview 只給 sandbox。

一分鐘腦內整理

讀完了？用這張收攏整節

連續、打包、預覽Continuous 立即收到；Bundled 每月第二個週二；Preview 只給 sandbox、早一個月。
Premium 一個、Enterprise 五個每個 app 免費 sandbox 的數量；Free 與 Standard 沒有。
28 天下線、30 天消失沒用 28 天變 Offline；Offline 超過 30 天永久刪除。
三種 release track 各收到哪些變更
  • Preview 只給 sandbox；production 只能選 Continuous 或 Bundled。
  • Bundled 擋不住 bug fix 與安全、效能更新。
切換 track 與建議的組合
  • 切換位置：Apps → Release management → Release tracks → Change track。
  • 推薦組合：production Bundled＋sandbox Preview。
Defer、freeze window 與四種選項
  • Defer 與 freeze window 都要 Enterprise。
  • Defer：公告後 10 天內、延後至少 30 天；freeze：最多 60 天前排、不含 sandbox。
Sandbox 是什麼、有幾個、誰能進
  • Premium 一個、Enterprise 最多五個（每個 app）；Free 與 Standard 沒有。
  • 剛建好只有 org admin 能進；其他人要加進 sandbox 的 group。
建立、停用、還原、重設
  • 28 天沒用變 Offline；Offline 30 天內可 Restore，之後永久刪除。
  • Reset 只能對 Online 的 sandbox 做，而且不能復原。
把資料複製進來、把設定部署出去
  • Copy 每次都覆蓋 sandbox 的資料；Marketplace app 與 access settings 不會複製。
  • Deploy 只支援 company-managed project 的設定。
