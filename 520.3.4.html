520.3.4・User management & access control 34%

Groups

Group 是管理存取最省力的方式：在 Atlassian Administration 用它給 app 角色，在 Jira 與 Confluence 裡用它設權限。這一節考 default group 的規則、建立與編輯 group，以及 site-admins 這類 admin group 的意義。

3 分鐘速覽

Group 的兩種用途與 default group 的規則

  1. 兩種用途在 Atlassian Administration 用 group 給 app 角色；在 Jira、Confluence 裡用 group 設 app 內權限。
  2. Default group每個 app 角色的主要 group；給人 app 存取時自動放進來。加 app 時每個角色會建一個，例如 confluence-users-{site}。
  3. Default group 規則每個角色至少要有一個；一個 group 同時只能當一個角色的 default；給 org admin 角色的 group 不能當 default；SCIM 同步的 group 不能當 default。
  4. 誰能設定 default groupDefault group 頁與排查頁都寫只有 org admin，user access admin 不行；但 original 介面的角色比較表把 site admin 列為可設定自己 site 的 default group，兩處說法不一。
  5. 建立與編輯Directory → Groups：Create group、Grant access、Add users、改名（beta）。Centralized 下 user access admin 只能管只給自己 app 的 group。
  6. site-admins／org-adminsOrganization 層的 admin group；centralized 下舊站的 site-admins group 其實連到 org admin 角色。

用途

一個 group，兩層用途

用途在哪裡設定誰設定例子
給 app 角色（第一層）Atlassian Administration：group → Grant accessOrg admin、user access admin（自己的 app）HR-team group 有 Confluence 與 JSM 的 User 角色
App 內權限（第二層）Jira：⚙ → System 與各 space 的權限；Confluence：⚙ → 權限設定Jira admin、Confluence admin只有 HR-confidential group 能看機密 space
  • 新人加入、換部門時，只要改他的 group，兩層權限一起跟著變：例如從 Legal-team 移到 HR-team。
  • Confluence 的 global permissions 只能給 group，不能給個人；Jira 的 global permissions 也是給 Organization admin 建立的 group。
  • Atlassian Cloud 不支援巢狀 group；從外部目錄同步時要攤平。
本段必考
  • Group 成員在 Admin 管、app 內權限在 app 設。
  • Confluence global permission 只能給 group。

Default groups

每個 app 角色的「入口 group」

Default group（2021 年 8 月後加的 app）給什麼
jira-users-{site}Jira 的 User 角色
jira-admins-{site}Jira Administration 的 App admin（Administer Jira 全域權限）
confluence-users-{site}／confluence-admins-{site}Confluence 的 User／App admin
confluence-guests-{site}Confluence guest：一次只能進一個 space
jira-servicemanagement-users-{site}JSM agent，計入 JSM 授權
{app}-user-access-admins-{site}User access admin；不給 app 存取、不計費
org-admins 或 site-adminsOrganization admin（管所有 site 與 organization）
  • 加 app 時，系統替每個角色建一個 default group；admin 改過名的話會和上表不同。舊 site（2021 年 8 月前）可能有 users、jira-users、site-admins 等舊名。
  • Default group 的規則：每個角色至少要有一個 default group；一個 group 可以給多個角色，但同時只能當其中一個角色的 default；給 org admin 角色的 group 不能當任何角色的 default（避免有人被給一般角色時意外變成 org admin）。
  • 小心授權暴增：自動放進 default group 若設定不當，會多用授權；改 JSM 的 default group 時，group 裡所有人都會占用 agent 授權。
  • system-administrators：Atlassian Support 用的 group，不能編輯或加人；裡面的 sysadmin 帳號不計授權。
本段必考
  • Default group＝角色的入口；每角色至少一個。
  • Org admin 的 group 不能當 default。

改 default group

先把角色給新 group，再設成 default

  1. 先給角色要當新 default 的 group，先在 Grant access 拿到該角色。
  2. CentralizedApps›Atlassian apps›Manage app → 新 group 的 ••• → Update default group setting → 選角色 → Update。
  3. OriginalApps → Atlassian apps → 該 app 的 ••• → View app → 新 group 的 ••• → Make this group default（重新整理才看得到標籤）。
  4. 拿掉舊的舊 group 的 ••• → Update default group setting 選 None（original：Don't make this group default）。這不影響 group 的成員與存取。

拿掉 default 標籤只是「之後新給存取的人不再自動放進這裡」，原本的成員與他們的存取都不變。要讓一個 group 不再給某 app，是另一個動作：從 group 移除該 app 的角色。

本段必考
  • 改 default 不影響現有成員與存取。
  • Centralized：Update default group setting；original：Make this group default。

site-admins group

Organization 層的 admin group

  • org-admins 或 site-admins：管理所有 site 與 organization 的人；有 user management、billing、所有 organization 與 site 設定、所有 app 的權限。
  • 舊名 site-admins（2021 年 8 月前）：管理一個 site 的人，可以管使用者、看 billing、使用 site 上所有 app。
  • Centralized 介面下，舊站的 site-admins group 其實連到 org admin 角色（名稱容易誤會）；新站則是 org-admins。Centralized 的 site admin 角色不連到任何 group，不能用 group 指派。
  • 把人加進 admin 角色的 default group，也是指派 admin 的一種方式（site admin 除外）。
考題長相

「把某人加進 site-admins group，他變成什麼？」在 centralized 介面下，這個 group 連到 org admin 角色，所以他會成為 org admin。官方建議 organization 至少有兩位 org admin。

本段必考
  • Centralized 下 site-admins group＝org admin 角色。
  • Site admin 角色（centralized）不能用 group 指派。
