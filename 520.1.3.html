3 分鐘速覽

誰管什麼、誰能指派誰

  1. Org admin最高層級：管使用者、group、app 與安全。只有 org admin 能指派 org admin、site admin、user access admin。
  2. Site admin管理一個 site：在 site 加 app、管 Marketplace app。Centralized 體驗下不能邀請或修改使用者。
  3. User access admin管理某個 app 的使用者存取，但自己不會自動取得這個 app 的存取。
  4. App admin管理某個 app 的設定（Jira admin、Confluence admin），不能進 Atlassian Administration。Jira 的 app admin 只有 org admin 能指派。
  5. Project admin／Space admin只管一個 Jira space 或 Confluence space；由 app admin 那一層（或 space 本身的權限）指派。
  6. 用 group 授權授予 admin 角色會把人加進對應的 default group；反過來，把人加進 jira-admins-{site}、org-admins 等 group 也能授權。Site admin 例外。
資料來源（5）有疑慮時點開看官方原文
  • What are the different types of admin roles?Only organization admins can add or manage other organization admins.
  • What are the different types of admin roles?A user access admin doesn’t automatically get access to the app they administer.
  • What are the different types of admin roles?An app admin can administer settings in a specific app. They don’t have access to Atlassian Administration. With the exception of the Jira family, app admins can access the content within the app they administer.
  • Give users admin permissionsRole: Organization admin, user access admin (only for the app they administer). Only an organization admin can make another user an app admin for Jira apps.
  • Give users admin permissionsThe same applies when you make someone an admin (except for site admin). We add the user to the default group for that admin role.

五種 admin

舊考綱：org、Jira、Jira project、Confluence、Confluence space

Admin權限從哪來做什麼不能做什麼
Org adminOrg admin 角色（org-admins 或 site-admins group）使用者、group、app 存取、安全政策、指派其他 admin角色本身不給 app 存取（系統另外自動給 user 與 app admin 角色）
Jira admin（Jira 的 app admin）Jira Administration 的 App admin 角色（jira-admins-{site}），即 Administer Jira 全域權限建 space、設定 work type、欄位、workflow 與各種 scheme不能管理使用者、匯入匯出資料、改系統 email；不會自動有 Jira 存取
Jira project admin（space admin）該 space 的 Administer Spaces 權限改 space 名稱、描述、lead、role 成員、components、versions只能看、不能換或改 scheme；改 space category 要 Jira admin
Confluence admin（Confluence 的 app admin）Confluence 的 App admin 角色（confluence-admins-{site}），即 Confluence administrator 全域權限Confluence 全站設定與全域權限有全域權限不代表有每個 space 的權限；要用 Recover Permissions 取得 space 的 admin
Confluence space admin該 space 的 Admin 角色或權限管理這個 space 的存取、內容與設定只管自己的 space

讀這張表時抓住一句話：app admin 管「整個 app」、project／space admin 管「一個 space」，而且 Jira 與 Confluence 的 admin 都不能指派 org 層級的角色。

考題長相

「Confluence admin 打不開某個 space 的權限設定」→ Confluence administrator 全域權限不等於每個 space 的權限。到 Confluence administration 的 Space permissions，對那個 space 選 Recover Permissions，就會取得該 space 的 admin 權限。

本段必考
  • Jira admin＝Administer Jira；Confluence admin＝Confluence administrator 全域權限。
  • Project／space admin 只管一個 space。
資料來源（7）有疑慮時點開看官方原文

授予與收回

怎麼把人變成 admin，再收回

  1. App adminDirectory → Users → 選人 → Grant access → 在該 app 的 Roles 欄選 App admin → Grant access。Jira 要改的是 Jira Administration 這一列，因為 Jira 家族共用同一個管理介面。
  2. User access admin同一個 Grant access 對話框，在該 app 選 User access admin。只有 org admin 能做。
  3. Site adminDirectory → Users → 選人 → ••• → Assign site admin role → 勾選 site → Grant。只有 org admin 能做；centralized 體驗下不能用 group 授予。
  4. Org adminDirectory → Users → 選人 → ••• → Assign organization admin role。只有 org admin 能做。
  5. 收回在使用者頁把角色改回、移除 admin 角色，或把他從對應的 default group 移除。
Default group給的角色
{app}-admins-{site}（例如 jira-admins-labjira）App admin
{app}-user-access-admins-{site}User access admin（不給 app 存取、不計費）
org-admins 或 site-admins（依建立時間只會有其中一個）Org admin

最後一列最容易誤會：在 centralized 體驗下，名為 site-admins 的 group 給的是 org admin 角色，不是 site admin。給 org admin 角色的 group 也不能被設成任何角色的 default group，免得有人在授予其他角色時意外成為 org admin。

Admin 不等於有 app 存取

Admin 角色不一定自動給 app 存取。Jira 的 app admin 要另外給 Jira 的 User 角色才能用 Jira；site admin 若要用 Jira 的功能，也需要 Jira 授權。

本段必考
  • Grant access 對話框：App admin、User access admin；••• 選單：site admin、org admin。
  • site-admins group（centralized）＝org admin 角色。
資料來源（5）有疑慮時點開看官方原文
  • Give users admin permissionsTo make someone an app admin for Jira, update the role for Jira Administration. This is because Jira apps share the same admin console. App admin is the only role that can be granted for Jira Administration.
  • Give users admin permissionsYou’ll only have one or the other, depending on when your organization was created. Regardless of the name, this group grants the organization admin role.
  • Give users admin permissionsEnsure that the user has the appropriate app license assigned. For example, some Jira functionality requires a Jira license even if the user is in the 'site-admins' group.
  • Understand default groupsNote, the group that grants the organization admin role can’t be a default group for any role. This prevents anyone from unintentionally becoming an organization admin when assigned another role.
  • Site Administrator role（KB）In the Centralized user management experience, the Site Admin role is not associated or linked to any group and therefore, Site Admin role assignment cannot be managed via a group.

實作 Lab：把 Kim 變成兩種 admin，再收回

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：親手授予 user access admin 與 Jira 的 app admin，從 Kim 的畫面看兩者能做和不能做的事，再收回。

這個 Lab 對應的考點

只有 org admin 能指派 org admin、site admin、user access admin 與 Jira 的 app admin；user access admin 不會自動有 app 存取；app admin 不能進 Atlassian Administration。

準備

  • Kim 有 Jira 的 User 角色，不是任何 admin。
  • Leo 有 Jira 的 User 角色，沒有 Confluence。

步驟

  1. 你應該看到：Kim 的角色清單多了 Confluence 的 User access admin；group 清單通常多了 confluence-user-access-admins-labjira。
  2. 你應該看到：Kim 看得到 organization 的使用者清單（user access admin 可以看使用者）。
  3. 你應該看到：成功：user access admin 可以把人加進自己管的 app。
  4. 你應該看到：做不到：Jira 家族的 app admin 只有 org admin 能指派。
  5. 你應該看到：Kim 的 group 清單多了 jira-admins-labjira；Jira Administration 只能選 App admin 這一種角色。
  6. 你應該看到：Kim 看得到 Jira 的全站設定（例如 Work items、System）。這是 app admin 的範圍，與 Atlassian Administration 無關。
  7. 你應該看到：兩個 admin group 從 Kim 的清單消失；Kim 的 ⚙ 通常只剩個人設定。
