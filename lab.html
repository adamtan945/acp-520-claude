動手做 Lab

Lab 環境準備

每一節最後都有一個「動手做 Lab」：在自己的測試 organization 照步驟點一次，看到 Atlassian Administration 的真實畫面、親手改一次設定，考題情境出現時腦中就有畫面。這一頁準備所有 Lab 共用的環境，只要做一次。

約 30 分鐘只在測試 organization 做

為什麼要動手

看過、點過、弄壞過，才記得住

  1. 看到畫面設定在 Atlassian Administration 的哪一頁、按鈕叫什麼。考題問「在哪裡設定」時，腦中直接浮現那一頁。
  2. 親手改一次改完用另一個帳號看結果，記住「因 → 果」。
  3. 故意弄壞每個 Lab 都有「試試看」：拿掉一個角色、刪一個測試 group，看會發生什麼。考題的錯誤選項通常就是這些情境。
  4. 留下心像錨點每個 Lab 最後有一句「閉上眼睛想一次這個畫面」，考前複習只要想這些畫面。
測試 organization

自己開一個，不要用公司的

  1. 建立用個人 email 註冊一個免費 Jira 站台（例如 labjira）。建站時會同時建立一個 organization，註冊的人就是 org admin。本教材稱它 Lab Org。
  2. 加 appAtlassian Administration›Apps 加 Confluence（Free）。需要「多個 site」的 Lab 再新增第二個 Jira site（例如 labjira2）。
  3. 試用需要付費方案的 Lab 用官方的免費試用：Release tracks 與 IP allowlisting 要 Premium 以上；Atlassian Guard 有 30 天免費試用。用完記得取消，避免轉成付費。
不要在公司正式 organization 做

Lab 會改 user access settings、刪 group、建 API key、改 authentication policy，有些會影響整個 organization。請只在自己的 Lab Org 做；在正式環境只做「看」的步驟。

測試帳號

三個人，用來切換視角

名字角色用途
你Org admin設定
Leo一般使用者被邀請、被暫停、被移除；觀察存取變化
Kim一般使用者之後當 user access admin 或 app admin 的範例
Ana不同網域的帳號外部帳號（external user）、access request 的範例
  1. 準備 email用 email 別名（例如 Gmail 的 你的帳號+leo@gmail.com）或其他信箱；Ana 要用和你不同網域的 email。
  2. 邀請Atlassian Administration›Directory›Users›Invite users：Leo、Kim 給 Jira 的 User 角色；Ana 先不要邀請（留給 access request 的 Lab）。
  3. 建 groupDirectory›Groups›Create group：建 lab-team，加入 Leo。
  4. 切換視角每個測試帳號用一個瀏覽器設定檔（Chrome profile）登入；無痕視窗當「未登入的路人」。
小技巧

做 Lab 時

  • Atlassian Administration 的網址是 admin.atlassian.com；有多個 organization 時先選對 organization。
  • 官方文件常分成 original 與 centralized 兩種 user management experience；你的畫面是哪一種，看 Users 在 organization 的 Directory 底下，還是在某個 site 底下。
  • 步驟前的方框可以打勾，進度只存在這台裝置。
  • 畫面和文字對不上時，用 Atlassian Administration 的搜尋找設定名稱；Atlassian 常改選單位置，但設定名稱大多不變。
  • Lab 做完一定做「收尾」：撤銷 API key、刪測試 group、取消試用。
