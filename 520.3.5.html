3 分鐘速覽

改了使用者或 group，Jira 與 Confluence 會怎樣

  1. 刪 group成員不會被刪；這個 group 給的 app 角色與 app 內權限一起失效。先移除權限再刪，否則日後建同名 group 權限會自動回來。Default group 不能刪。
  2. 從 group 移除 app成員若還在其他給同一 app 的 group，存取不變。
  3. 改 group 名稱被 Jira 設定（例如 filter 的 JQL）使用時不能改；改了 automation 用到的名稱，rule 會停。
  4. Suspend、remove、deactivate都會停止計費。Suspend 保留角色與 group，deactivate 不刪個人資料；remove 對內容的影響官方說法不一（見下表）。
  5. Delete managed account14 天後永久刪除，名字變成 Former user；建立的內容不刪。用 IdP 同步的要先從 IdP 移除。
  6. 排查順序使用者狀態 → app 角色（哪些 group 給的）→ app 內權限 → 是否 SCIM 唯讀 group → Log in as user 重現。

Jira

Group 與使用者變更在 Jira 的影響

變更在 Jira 會看到什麼怎麼處理
刪除 permission scheme、global permissions 用到的 group原成員失去透過這個 group 拿到的權限（看不到 project、不能 bulk change…）刪之前先查 Jira 的 global permissions、permission scheme、filter 分享等；不需要時先移除權限再刪
改 group 名稱被 Jira 管理設定使用時改不了；錯誤訊息會列出是哪種設定（例如 JQL Filters）先改掉或刪掉引用這個 group 的 filter，再改名，再把 filter 改回新名稱
改 automation 用到的 group 名稱Rule 停止運作改名後更新 rule
使用者被 deactivateDeactivate 是 user management 的事件，不是 Jira 的事件；他的 work item 仍掛在他名下用 JQL assignee in inactiveUsers() 找出來，重新指派
把 org admin 或 site admin 當成 Jira adminOrg／site admin 本身不一定有 Administer Jira加進 jira-administrators（或 jira-admins-{site}）

Jira 的 global permissions 是給 group 的，所以 group 的增刪會直接改變誰能做全站層級的事。Jira admin 能改權限設定，但不能管使用者；要改 group 成員，要找 org admin 或 user access admin。

本段必考
  • Group 被 Jira filter 或設定引用時不能改名。
  • 用 inactiveUsers() 找停用者名下的 work item。

Confluence

Group 與使用者變更在 Confluence 的影響

變更在 Confluence 會看到什麼怎麼處理
移除某個給 Confluence 的 group只靠這個 group 進 Confluence 的人失去存取確認他們是否還在其他給 Confluence 的 group
要讓某一個人不能用 ConfluenceConfluence 不能單獨移除一個人把他移出所有給 Confluence 的 group，或移除那些 group
刪除 space 權限用到的 group原成員失去這個 space 的存取刪之前先查 space 的 Users（角色）設定
唯一的 space admin 離職沒有人能管這個 space 的權限Confluence admin 用 Recover Permissions 暫時成為 space admin，再指派新 admin
Free 方案Global permissions 不能自訂升級付費方案才能編輯
  • Confluence 的 licensed users 都是以 group 成員的身分進來；global permissions 只能給 group。只有 site admin、user access admin、org admin 能替 Confluence 加或移除 group。
  • Space 權限（role-based access）可以給 user、group、team 或 user class（例如 All Confluence users），所以並非所有權限都靠 group。
  • 匿名存取不計授權。
本段必考
  • Confluence 存取全靠 group：要擋一個人，就把他移出所有給 Confluence 的 group。
  • 唯一 space admin 離職 → Recover Permissions。

排查

使用者說「我進不去」

  • Invited 狀態卡住或 IdP 同步後仍進不去：檢查 group 與 app 角色的對應是否完整、app 內權限（例如 Jira company-managed project 的 Browse Projects）是否正確。
  • User access admin 給不了或收不了存取：該 app 的 default group 也給了他不管的 app，或使用者在另一個也給其他 app 的 group 裡。找 org admin 改 default group，或讓他也成為那些 app 的 user access admin。
  • 收不了 SCIM 使用者的存取：SCIM group 是唯讀的，要在 IdP 把人移出；從 IdP 同步的使用者也不會自動放進 default group。
  • 邀請失敗：被 deactivate 或停用的帳號不能被邀請，要先重新啟用（managed account 由擁有它的 organization 處理）。
  • 刪了 managed account 又出現：用 IdP 同步時，要先從 IdP 移除，否則帳號會被重新建立。
本段必考
  • 先看狀態與角色，再看 app 內權限，最後看同步來源。
  • SCIM group 唯讀：在 IdP 改。

多個 organization

跨 organization、site 的變更

  • 每個 organization 各有一份使用者與 group；同一個帳號在 A organization 被 remove 或 suspend，不影響他在 B organization。Managed account 被 deactivate 或 delete，則在所有 organization 都不能用。
  • Original 介面：每個 site 各自管理使用者與 group；remove user 只移出這個 site，不影響同 organization 的其他 site。
  • 合併 organization（consolidation）時：同名 group 會被改名；同一個帳號在一邊 active、另一邊 inactive，合併後會變成 inactive；來源 organization 的 org admin 會成為目的地的 org admin。
  • 合併後 IdP 由目的地 organization 管理，會把使用者佈建到所有 site，可能讓人拿到原本沒有的 site 存取。
考題長相

「承包商同時在公司兩個 organization 都有存取，只要從其中一個收回」：在那個 organization Remove user。Deactivate 會讓他在所有 organization 都不能用，而且只對 managed account 可行。

本段必考
  • Remove／suspend：只影響這個 organization（original：這個 site）。
  • Deactivate／delete：帳號層級、所有 organization。

刪除 group 會一併刪除成員。
成員還在 organization；只有透過這個 group 拿到的存取與權限失效。

刪 group 後再建同名 group，就是全新的乾淨 group。

還在其他給同一 app 的 group 的人不受影響。

Delete managed account 會刪掉他建立的 Jira work item 與 Confluence page。
內容保留，作者顯示為 Former user；刪的是個人資料。

Deactivate 是 Jira 事件，可以用 Jira automation 的觸發器直接接。
Deactivate 是 user management 的事件；用排程 rule 搭配 inactiveUsers() 找出受影響的 work item。

Confluence 可以單獨把一個人從 Confluence 移除，不動 group。
Confluence 存取來自 group；要把他移出所有給 Confluence 的 group。

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：親眼看 group 被 Jira filter 引用時改不了名、從 group 移除 app 時誰會受影響，以及刪 group 不會刪人。

這個 Lab 對應的考點

Group 被 Jira 設定（例如 filter 的 JQL）使用時不能改名；從 group 移除 app，還在其他給同一 app 的 group 的人不受影響；刪 group 不刪成員，但權限會跟著消失。

準備

  • Leo、Kim 都有 Jira（來自 Jira 的 default group）。
  • Leo 在 lab-team；Kim 不在。

步驟

  1. 你應該看到：lab-ghost 有兩位成員、有 Jira 的 User 角色。
  2. 你應該看到：Filter 存檔成功。
  3. 你應該看到：通常會被擋下，錯誤訊息列出引用這個 group 的 Jira 設定（例如 JQL Filters）。
  4. 你應該看到：改名成功，現在叫 lab-ghost2。
  5. 你應該看到：Leo 仍然能用 Jira：他還在 Jira 的 default group 裡。
  6. 你應該看到：Group 消失；Leo 與 Kim 仍在 Users 清單，只是 Groups 少了 lab-ghost2。
  7. 你應該看到：通常清單裡的對象都是 group（global permissions 只能給 group）；Free 方案不能自訂 global permissions，只看不改。

試試看：改一個設定，觀察差異

T1把 lab-team 加上 Confluence 的 User 角色，確認 Leo 只靠 lab-team 拿到 Confluence；再把 Confluence 從 lab-team 移除。看結果
Leo 失去 Confluence：他沒有其他給 Confluence 的 group。和步驟 5 對照：受影響的只有「只靠這個 group」的人。

原本給這個 group 的權限會自動套回新的同名 group；所以官方建議先移除權限再刪 group。

Deactivate 是 user management 的事件，不是 Jira 的事件；在 Jira 用 assignee in inactiveUsers() 找出她名下的 work item 重新指派。
