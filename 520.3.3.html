520.3.3・User management & access control 34%

管理使用者

這一節是日常管理：用 app 角色給與收回存取、暫停與移除、以使用者身分登入檢查，以及 managed account 才能做的事。每一項都要分清 centralized 與 original 下誰能做。

3 分鐘速覽

給角色、收角色、暫停、移除、以使用者身分登入

  1. Grant access在使用者（或 group）頁按 Grant access、選 app 角色；系統把他放進該角色的 default group。
  2. Remove access從使用者的 Apps 分頁移除某 app：把他從所有給這個 app 的 group 拿掉；人仍在 organization。Org admin 要先拿掉 admin 角色。
  3. Suspend／Restore暫停存取、不計費；Restore 後角色與 group 原樣回來。
  4. Remove user移出 organization（original：移出 site）、不計費；要重新邀請並重設角色與 group。不影響他在其他 organization。
  5. Log in as userOrg admin 用來檢查權限；不能登入成另一個 org admin、還沒用過 app 的人、portal-only customer；會 email 通知本人。
  6. Managed account只有 managed account 能改資料、重設密碼、deactivate、delete；external user 只能 suspend 或 remove。

暫停與移除

由輕到重的五種動作

動作影響範圍計費怎麼恢復
Suspend accessCentralized：這個 organization；original：這個 site✗ 不計費Restore access：角色與 group 回來
Remove userCentralized：移出 organization；original：移出 site✗ 不計費重新邀請，並重新指定角色與 group

Remove user 對內容的影響，官方兩份文件說法不一：Remove user 頁說會移除他的部分內容，請你先看 Delete your Atlassian account 或 Delete a managed account 頁確認哪些資料會被刪；Users 與 Managed accounts 頁差異的 KB 則說移出 site 不影響帳號在 site 上的歷史資料與活動。作答時兩種說法都要認得。誰能做：centralized 是 org admin，以及 user access admin（只限沒有 app 存取、或只有他所管 app 的使用者）；original 是 org admin 與 site admin。Deactivate、delete 只有 org admin 能做，細節見 520.4.1。

User access admin 是 centralized 介面才有的角色：他管某一個 app 的使用者存取，但自己不一定有這個 app 的存取。Centralized 的 site admin 管 site 上的 app，不管人；如果要讓他管人，再給他該 app 的 user access admin 角色。Centralized 下指派這些 admin 角色只有 org admin 能做；original 下 site admin 也可以指派或移除 site admin 角色（520.1.3 詳述）。

本段必考
  • Centralized 的 site admin 不能邀請或修改使用者。
  • User access admin 只管自己那個 app 的存取。

考題愛用的錯誤說法

把人從 default group 移除，他一定就不能用這個 app。
其他 group 也可能給同一個 app；要從所有給該 app 的 group 移除（Remove access 會一次做完）。
官方來源
Remove user 之後 restore，group 會回來。
Remove 要重新邀請並重設角色與 group；能原樣回來的是 suspend → restore。
官方來源
從我們 organization 移除某人，他在其他 organization 也不能用了。
Remove user 不影響其他 organization，也不刪除他的帳號。
官方來源
Site admin 在 centralized 介面也能 Log in as user。
Centralized 只有 org admin 能用；original 的 site admin 可以（但不能登入成同級或更高的人）。
官方來源
可以 deactivate 任何離職者的帳號。
只能 deactivate、delete managed account；external user 只能 suspend 或 remove。
官方來源
要收回 org admin 的 Jira 存取，直接 Remove access 即可。
要先拿掉他的 org admin 角色。

動手做

實作 Lab：給角色、暫停、代登、移除

約 25 分鐘Org admin；所有方案

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：在同一個使用者頁面做一輪：給與收回 app 角色、suspend 與 restore、Log in as user，再對一個測試帳號做 remove。

這個 Lab 對應的考點

Remove access 會把人移出所有給該 app 的 group；suspend → restore 角色與 group 原樣回來，remove 要重新邀請；centralized 下只有 org admin 能 Log in as user，而且不能登入成還沒用過 app 的人。

準備

  • 準備一個新的 email 別名 Mia（只在這個 Lab 用，最後會移除）。
  • Leo 在 lab-team。

步驟

  1. 你應該看到：Kim 的 Apps 分頁多了 Confluence；Groups 多了 confluence-users-labjira 這類 default group。
  2. 你應該看到：Confluence 從 Apps 消失，Kim 也被移出給 Confluence 的 group；Kim 仍在 Users 清單。
  3. 你應該看到：Leo 的狀態變成 Suspended；Leo 不能用 Jira。
  4. 你應該看到：Leo 的 Jira 角色與 lab-team 都回來了。
  5. 你應該看到：畫面顯示你正以 Leo 的身分登入，看到的是 Leo 看得到的內容；Leo 會收到 email 通知。
  6. 你應該看到：通常看不到可用的 Log in as user：不能登入成還沒用過 app 的人。
  7. 你應該看到：Mia 從 Users 清單消失，不再計費；要回來得重新邀請並重設角色與 group。
  8. 你應該看到：Kim 看得到 Directory 的使用者；App access settings 通常看不到或不能改（只有 org admin 能設定）；Kim 本人沒有因此拿到 Confluence 的使用權。

試試看：改一個設定，觀察差異

T1用 Kim（Confluence 的 user access admin）替 Ana 加 Confluence（Leo 在 520.3.2 已經有 Confluence），再試著收回 Leo 的 Jira。看結果
Confluence 可以（只要 Confluence 的 default group 沒有連帶給其他 app）；Jira 她不管，所以收不了。這就是「只限自己管的 app」。
T2用 Kim 試著在 Leo 的頁面找 Log in as user。看結果
找不到或不能用：centralized 下只有 org admin 能 Log in as user。
T3（想像，不實際做）對 Leo 做 Remove user 再重新邀請。看結果
Leo 回來時 lab-team 不見了；要重新指定角色與 group。能原樣回來的是 suspend → restore。
