3 分鐘速覽

多個 site、app URL、轉移與 landing app

  1. Organization、site、appOrganization 集中管理使用者、安全與帳單。Site 是一個網址（xxx.atlassian.net），同一個 site 上的 app 共用這個網址，而且每個 site 有自己的帳單。
  2. 一個方案一個 instanceFree、Standard、Premium 方案各只給一個 app instance；Enterprise 方案可以在同一個方案下有最多 150 個 instance。
  3. 新增 appOrg admin 在 Apps → Atlassian apps → Add app 加入新 app。新 app 從 Standard 或 Premium 試用開始，沒有付款資料時，試用結束會改成 Free。
  4. 改 URLApps → App URLs → Update URL 只能改 atlassian.net 前面的 subdomain，整個 site 的 app 一起改。舊網址在瀏覽器會自動轉址，但 REST API 呼叫舊網址會失敗（401）。
  5. 轉移 app在要淘汰的 organization 選 Organization settings → Profile → Transfer apps。兩邊都要是 org admin，而且只適用 original user management；轉移不能復原。
  6. Landing app使用者打開 site 網址時先看到的 app，只能選 Jira 或 Confluence。最多兩小時生效；沒有該 app 存取的人會被提示申請存取。

結構

Organization、site 與 app instance

層次是什麼考點
Organization把公司的使用者與 app 集中管理的單位；org admin 在 Atlassian Administration（admin.atlassian.com）管理它使用者、group、安全政策與帳單都在這一層設定
Site一個網址，例如 labjira.atlassian.net；第一次註冊 app 時取的 site 名稱，會變成網址的 subdomain每個 site 有自己的帳單；改 URL 也是以 site 為單位
App instance某個 app 的一份獨立副本，例如 labjira 上的 Jira 與 labjira2 上的 Jira 是兩個 instance內容很難在 instance 之間搬移，所以官方建議事先規劃

為什麼要分成多個 instance？官方列出四類理由。第一是管理自主：把某些 instance 的 app 管理交給團隊自己做，敏感或公開的 instance 留在中央控管。第二是安全與資料隔離：每個 instance 可以分別控制誰能存取與管理、audit log 的層級與資料存放地區。第三是併購：先把對方的 instance 收進 organization 集中管理，使用者照常在原本的 instance 工作。第四是Marketplace 成本：每個 instance 分別訂閱 Marketplace app，計費人數也分開算。

考題長相

「公司想讓研發與法務各用一個 Jira instance、資料彼此隔離，又希望放在同一個方案底下」：Enterprise 方案可以在同一個方案下有最多 150 個 instance；Free、Standard、Premium 方案每個只有一個 instance，要多個就得分別訂閱。

本段必考

  • Site 是網址單位，也是帳單單位；instance 之間很難搬內容，要先規劃。

新增 app

在既有 organization 加 app 與 site

  1. 位置Atlassian Administration›Apps›Atlassian apps，按 Add app，依提示設定 app，最後按 Add／Start trial。
  2. 方案新加的 app 從 Standard 或 Premium 的免費試用開始；試用結束後開始計費。如果沒有付款資料，app 會改成 Free 方案。
  3. 建好之後建立可能要幾分鐘，完成後會寄 email 通知，app 也會出現在 organization 的 app 清單。
  4. 誰能做Org admin 可以把 app 加進 organization；site admin 只能在自己管理的 site 上加 app。

URL

Site URL、app URL 與 custom domain

  1. 位置Atlassian Administration›Apps›App URLs，在要改的 site 那一列按 Update URL。
  2. 輸入新名稱至少 3 個字元，可用小寫英文字母、數字，連字號只能放在中間。
  3. 確認按 Continue，畫面會列出會一起改用新網址的 app，再按 Update。最多 5 分鐘完成。
改 app URL 的 subdomainCustom domain
網址長什麼樣acme.atlassian.net：只能改 atlassian.net 前面那段customer.help.acme.com：使用公司自己的網域
方案條件該 site 至少要有一個 Standard、Premium 或 Enterprise 方案的 Jira 或 Confluence要 Jira Premium、Confluence Premium 或 Jira Service Management Standard
要不要改 DNS不用改 DNS，幾乎立即可用要在 DNS 加幾筆紀錄證明擁有網域，生效需要時間
次數與重用有次數上限；用過的網址不能再用沒有次數限制，也能重用以前的網域名稱
支援範圍相容所有 Marketplace 與第三方整合只支援 Jira 家族、JSM help center 與 Confluence，也不一定相容所有整合
  • 改完之後，舊網址會記在 site 的歷史裡，所有連結（例如 Jira issue、Confluence 頁面）都會轉到新網址，所以舊網址也不能給別的 site 用。
  • REST API 整合要改用新網址：瀏覽器會轉址，但 API 呼叫舊網址會回 401。Partner-built apps 可能要重新設定或重新安裝。
  • Sandbox 的 URL 不會跟著改；想改 sandbox 網址要重建 sandbox，或用 sandbox 自己的 Update sandbox URL。
  • Jira 與 Jira Service Management 的 Atlassian email 地址會改成新 site 名稱的格式，新舊地址都能收信。
改幾次？兩份官方文件寫法不同

Update an app URL subdomain 頁寫 subdomain 最多可以改 15 次；Can I update the URL 頁的限制清單與比較表則寫不能超過 3 次。作答時抓住共同點：次數有上限、用過的網址不能再用。方案條件也不一致：Update 頁的 Who can do this 方框列 Jira Premium、Confluence Premium 或 Jira Service Management Standard，內文寫要有至少一個付費 app；Can I update 頁則寫該 site 要有 Standard、Premium 或 Enterprise 的 Jira 或 Confluence。

本段必考
  • 改 URL 是整個 site 一起改，不能只改一個 app。
  • 舊網址在瀏覽器會轉址，REST API 會回 401。
  • Custom domain：Jira／Confluence Premium 或 JSM Standard，而且要加 DNS 紀錄。

轉移

把 app 轉移到另一個 organization

轉移前要先處理的設定做法
SAML SSO、user provisioning先在 Atlassian 這端中斷連線（不要 de-provision group，才能保留 group 與權限），轉移後在新 organization 重新連 IdP
Admin API keys在 API keys 頁撤銷；轉移後在新 organization 建新的 key，並更新整合
Atlassian Guard 訂閱先取消，轉移後重新訂閱
Enterprise 方案先取消，轉移後重新訂閱
Rovo 訂閱與 AIRovo 訂閱要請 billing support 停用；每個 app 的 AI 也要先在 Rovo → Rovo access 關掉，轉移後再開
Domains 與 email domains已驗證與未驗證的都要移除，轉移後在新 organization 重新驗證（DNS 最多可能要 72 小時）
Approved domains、user invites、invitation links在目的 organization 的每個 site 重新設定

不會改變

使用者端
  • 使用者不會停機，app 存取與權限不變
  • App 保留原本的 URL、權限、projects、spaces
  • 原本的 app admin、site admin 仍是 admin
  • 同樣的 app 不會合併，會變成多個 instance

會改變

管理端
  • 來源 organization 的 org admin 會變成目的 organization 的 org admin，也成為所有 site 的 site admin
  • 這些 admin 若因此拿到原本沒有的 app 存取，帳單可能增加
  • SSO 還沒在新 organization 設好前，使用者可能要暫時設密碼登入
  • 空的 organization 會被刪除
考題長相

「兩家公司合併，要把 B 公司的 Jira 搬到 A 公司的 organization」：在 B 的 organization 執行 Transfer apps，你必須同時是兩邊的 org admin。如果任一邊是 centralized user management，就不能自助轉移，要聯絡 Atlassian support。

本段必考
  • Transfer apps 在要淘汰的 organization 執行，兩邊都要是 org admin。
  • 轉移不能復原；同類 app 不會合併。
  • 來源 org admin 會變成目的 org 的 org admin 與所有 site 的 site admin。

動手做

實作 Lab：加第二個 site，再換 landing app

約 20 分鐘Org admin（Free 方案即可；從 Atlassian Administration 新增 app 時，會先進入 Standard 或 Premium 試用）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：親眼看一個 organization 底下的多個 site 與 app，看 App URLs 頁怎麼以 site 為單位改網址，再把 landing app 換掉、用 Leo 的視角看結果。

這個 Lab 對應的考點

Site 是網址與帳單單位，改 URL 是整個 site 一起改；landing app 只能選 Jira 或 Confluence，最多兩小時生效；Transfer apps 在要淘汰的 organization 執行，centralized user management 不能自助轉移。

準備

  • Leo 只有 labjira 的 Jira 存取，沒有 Confluence 存取。
  • 如果還沒建 labjira2，步驟 2 會建。

步驟

  1. 你應該看到：看到 labjira 上的 Jira 與 Confluence；如果已經建了 labjira2，也會看到它的 Jira。每個 app 通常會標出它所在的 site 網址。
  2. 你應該看到：建立要幾分鐘，完成會收到 email；新的 Jira 從 Standard 或 Premium 試用開始，試用結束沒有付款資料會變成 Free。
  3. 你應該看到：一列是一個 site；labjira 那一列同時列出 Jira 與 Confluence，代表它們會一起換網址。輸入框要求至少 3 個字元。官方規定該 site 要有 Standard 以上（付費）的 Jira 或 Confluence；labjira 若都還是 Free，Update URL 可能是停用狀態，那就只看 labjira2 那一列。
  4. 你應該看到：下拉選單只有 Jira 與 Confluence 可以選；每個 site 各有一個設定。
  5. 你應該看到：生效後 Leo 會被帶到 Confluence，並看到申請存取的提示，因為他沒有 Confluence 存取。先不要送出申請（520.3.2 再處理）。
  6. 你應該看到：Lab Org 用的是 centralized user management（Users 在 Directory 底下），官方說這種 organization 不能自助轉移 app；畫面上通常看不到可用的 Transfer apps，或會引導你聯絡 support。

一分鐘腦內整理

讀完了？用這張收攏整節

一網址一帳單Site 是網址單位，也是帳單單位；改 URL 是整個 site 一起改。
舊家按轉移、搬過去不合併Transfer apps 在要淘汰的 organization 執行；同類 app 轉移後仍是不同 instance。
落地只有 J 和 CLanding app 只能是 Jira 或 Confluence。
Organization、site 與 app instance
  • Free／Standard／Premium：一個方案一個 instance；Enterprise：同一方案最多 150 個。
  • Site 是網址單位，也是帳單單位；instance 之間很難搬內容，要先規劃。
在既有 organization 加 app 與 site
  • 新增 app：Apps → Atlassian apps → Add app。
  • 試用結束沒有付款資料就變 Free；JPD 只能加到既有 site。
Site URL、app URL 與 custom domain
  • 改 URL 是整個 site 一起改，不能只改一個 app。
  • 舊網址在瀏覽器會轉址，REST API 會回 401。
  • Custom domain：Jira／Confluence Premium 或 JSM Standard，而且要加 DNS 紀錄。
把 app 轉移到另一個 organization
  • Transfer apps 在要淘汰的 organization 執行，兩邊都要是 org admin。
  • 轉移不能復原；同類 app 不會合併。
  • 來源 org admin 會變成目的 org 的 org admin 與所有 site 的 site admin。
使用者登入 site 時先看到哪個 app
  • Landing app 只能是 Jira 或 Confluence，每個 site 各設一個。
  • Centralized 只有 org admin 能設；original 介面 site admin 也能設。
